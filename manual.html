1. Introduction

LysiPOS is a single, installable web app that combines three things a small business usually pays for separately: a Point of Sale (ring sales, print receipts), a Customer Relationship Manager (track buyers, tags, notes, loyalty points), and light SaaS-style business admin (users & roles, settings, reports, backups).

Everything runs in your browser. There is no server to configure — your catalog, customers, and sales are stored locally in IndexedDB, and the app installs as a PWA so it opens like a native app and works offline.

Who should use this manual? Store owners, managers and cashiers. Sections marked Admin are only visible to users with the admin role.

2. Install as an app (PWA)

LysiPOS is a Progressive Web App — you can install it to your desktop, iPad, or Android phone and it will behave like a native app (own icon, no browser tabs, offline support).

Desktop (Chrome, Edge, Brave, Arc)

  1. Open index.html served over http://localhost or https://. (Opening it from a plain file:// path will work, but PWA install and the service worker require a real HTTP origin.)
  2. Look for the Install icon in the address bar, or click the ⤓ Install App button in the sidebar.
  3. Confirm — LysiPOS now appears in your Start menu / Dock.

iPhone / iPad (Safari)

  1. Open the URL in Safari.
  2. Tap Share → Add to Home Screen.
  3. Launch it from the home screen — the URL bar disappears and it runs full-screen.

Android (Chrome)

  1. Open the URL, then tap the ⋮ menu.
  2. Choose Install app or Add to Home screen.
Local demo tip: to run over HTTP, use any static server. For example, from the project folder run python -m http.server 8080 and open http://localhost:8080.

4. Interface tour

The app has three regions:

  • Sidebar (left): navigation, theme toggle, install button, and a link to this manual.
  • Top bar: business name badge, online/offline pill, current user, and logout.
  • Main area: the current page.

On small screens the sidebar hides behind a ☰ button in the top bar.

5. Selling — the POS

Open Point of Sale from the sidebar. The screen has two halves:

  • Left — catalog: a grid of product tiles with a search box and a category filter.
  • Right — cart: current sale, running total, and the Charge button.

Ringing a sale

  1. Type in the search box or click a product tile to add it. Out-of-stock items are dimmed and can't be added.
  2. In the cart, use − / + or type a quantity directly.
  3. Optionally click Customer to attach a customer to the sale (needed for loyalty points).
  4. Click Charge. The Checkout dialog opens.
  5. Pick a payment method (Cash / Card / Wallet), enter the amount tendered, adjust the discount if any, then Charge.
  6. A receipt appears — click Print receipt to send it to your printer, or close to go back.

Barcode scanning

The search box is focused by default. Most USB / Bluetooth barcode scanners act as a keyboard: they type the code and press Enter. If a product matches the scanned code exactly (by barcode or sku) it is added to the cart automatically.

Holding a sale

Click Hold to save the current cart aside — useful when a customer runs to grab one more thing. Next time you open the POS screen the held cart is restored.

Discounts and tax

Discounts are entered as an absolute amount (in your currency) in the checkout dialog. Tax is calculated using the rate set in Settings → Money. Items marked non-taxable are excluded from the taxable subtotal.

6. Products & categories

Open Products to manage your catalog.

  • Click + New product to add. Fields: name, SKU, barcode, category, price, cost, stock, taxable, active.
  • Edit reopens the same form. Delete removes the product (past sales keep their line items but link to a missing product).
  • Categories opens a simple manager where you can add or remove categories.
Set Active: No to hide a seasonal product from the POS without deleting it.

7. Inventory

Open Inventory to adjust stock. Type a positive number to add units, or negative to remove them, then Apply. The Bulk restock (+10 all) button is handy for demos.

Sales automatically decrement stock. Refunds (see §9) automatically restore it.

8. Suppliers

Open Suppliers to manage the vendors you buy inventory from.

  • + New supplier: name, contact person, email, phone, payment terms (e.g. Net 30, COD, Prepaid), address, tags, and notes.
  • Open a supplier to view all linked products (with SKU, cost and current stock) and edit their details.
  • Search by name, contact, email or tag. The Products column shows how many items each supplier sources.

Linking products to a supplier

Every product now has a Supplier dropdown in its edit form (Products → Edit). Assign a supplier to answer questions like "who do we reorder this from?" and "which vendor supplies most of our stock?" Deleting a supplier automatically clears the link on any product that used it — the products stay, they just lose the supplier assignment.

Suppliers are included in JSON backups and the Products CSV export (as an extra Supplier column).

9. Barcodes, QR & labels

LysiPOS ships with three built-in ways to work with codes — no external libraries, everything runs offline.

Generate a barcode or QR for a product

  1. Open Products → Edit on any item.
  2. The Label preview card renders a live Code128 barcode of the Barcode field (falling back to the SKU when Barcode is empty).
  3. Click ▦ Show QR to switch to a QR code that encodes JSON with name, SKU, barcode and price — any consumer QR reader will show the details.
  4. Click ⤓ Download SVG to save the current preview as a vector file you can drop into your label designer.
  5. The = SKU button copies the SKU into the Barcode field; the 📷 button opens the camera scanner to fill Barcode from a scan.

Print a sheet of labels

Open Labels from the sidebar. The page is a paper-accurate designer:

  1. Filter and check the products you want, and set a quantity per product.
  2. Pick Type (Barcode or QR).
  3. Pick Paper — A4 (210 × 297 mm), Short bond / Letter (8.5 × 11 in), or Long bond / Legal (8.5 × 14 in) — and Orientation (Portrait or Landscape).
  4. Choose Cols × Rows per page (from 2×4 up to 6×12) and Margin (5, 8, 10 or 15 mm). The header shows the resulting cell size in millimeters so you can match a specific label sheet.
  5. The preview renders each printable page at real proportions, with page breaks shown between them. Empty cells on the last page appear faintly outlined.
  6. Click 🖨 Print — the app injects a matching @page size rule so the printer uses the exact paper size and orientation you chose. The sidebar, top bar, and configuration panels are hidden by print CSS so only the label pages print.
In the browser's print dialog, make sure "Scale" is set to 100% and any "Fit to page" option is off, or the label dimensions will drift from the mm values shown in the header.

Scanning barcodes and QR with the camera

The 📷 Scan button on the POS opens the camera scanner using your browser's native BarcodeDetector:

  • Supported on Chrome / Edge on Android, and Safari on iOS 17+. On unsupported browsers the button warns and you can continue using a USB / Bluetooth keyboard-wedge scanner into the search box.
  • The first detected code (EAN-13, EAN-8, Code128, Code39, UPC-A/E, QR, ITF, Codabar) auto-matches to a product by Barcode or SKU; if there's no match, the scanned value drops into the search box so you can review.
  • The 🔄 button flips between front and back camera. Grant camera permission the first time; iOS also requires you to be on https:// or http://localhost.
The QR generator supports up to about 213 characters (version 10 at error-correction level M). Enough for URLs, product JSON, and long SKUs. If you feed it more it will refuse rather than truncate.

10. Customers (CRM)

Open Customers to manage your CRM.

  • + New customer: name, email, phone, address, tags (comma-separated), notes.
  • Open a customer to see lifetime spend, order count, points, and the interaction log.
  • Use Add interaction note to log phone calls, complaints, or anything else worth remembering. Purchases are logged automatically when a sale is attached to the customer at checkout.

Loyalty points

Every attached sale earns points according to Settings → Money → Loyalty pts per {currency}. Set 1 pt worth if you plan to redeem points as store credit in the future.

11. Sales history & refunds

Open Sales to see every completed sale, filter by date range or receipt number, and see the running total for the current filter.

  • Click View on any row to open the receipt.
  • From the receipt dialog, Print re-prints it or Refund reverses the sale — the sale is marked refunded and stock is restored.

12. Reports & exports

Open Reports for a rolling 30-day view: revenue, items, average ticket, a daily bar chart, and breakdowns by category and cashier.

Under Export:

  • Sales CSV — one row per sale, with subtotal, discount, tax, total, method, and refund status.
  • Products CSV — your full catalog.

Both files open in Excel, Numbers, or Google Sheets.

13. Users & roles (Admin)

Open Users. Add teammates and assign one of three roles:

RoleCan do
adminEverything, including user management and resetting data.
managerEverything except managing users.
cashierRing sales, look up products and customers, refund from history (if permitted by store policy).

Editing a user with the password field blank keeps the existing password. Deactivate a user by setting Active: No instead of deleting them — this preserves their name on past receipts.

14. Settings, tax & currency

Open Settings. Fields:

  • Business: name, address, phone, email, receipt footer.
  • Currency: any ISO-4217 code (USD, EUR, GBP, NGN, ZAR, INR, …). Formatting follows the browser locale.
  • Tax rate: percentage. Set Tax included in price to Yes if your displayed prices already include tax (common outside the US) — the app will extract the tax from the price instead of adding it on top.
  • Loyalty: points per unit currency spent, and the value of one point.
  • Theme: Dark or Light.

Click Save settings — the sidebar and receipt update immediately.

15. Backup, restore & reset

Under Settings → Data:

  • Export backup (JSON) saves a single file containing all products, categories, suppliers, customers, sales, users, expenses and settings. Keep this file somewhere safe (cloud drive, USB stick).
  • Import backup replaces the current data with the contents of a chosen JSON backup. The importer auto-detects two formats: LysiPOS's own backups, and Convex-style exports from other POS systems (fields like _id, _creationTime, and a separate saleItems array are converted automatically — product categories and suppliers come across intact).
  • Reset all data wipes everything and re-seeds the demo store.
Warning: Import and Reset are destructive. Export first.

Auto-backup

Under Settings → Auto-backup:

  • Frequency: Off, Daily, or Weekly. The app checks at start-up (and every 6 hours it's kept open) and only runs one backup per interval.
  • Keep last N backups: rolling window inside the app; older ones are pruned automatically.
  • Backup folder (Chrome/Edge): click Choose folder… once and grant read/write. Each auto-backup will then also be written to disk as lysipos-backup-YYYY-MM-DD.json in that folder — no download prompt. Other browsers fall back to in-app backups only.
  • Run backup now: manual trigger.

Under Rolling backups you'll see every stored snapshot with buttons to Download, Restore, or Delete individually.

Because folder permission is per-session, Chrome may re-prompt for access the first time an auto-backup fires after each app relaunch — a one-click confirmation.

16. Offline & data safety

LysiPOS is offline-first. Once installed, the app shell (HTML/CSS/JS/icons) is cached by the service worker and all data lives in your browser's IndexedDB. You can sell, add customers, and adjust inventory with no internet connection.

The online/offline pill in the top bar reflects the browser's connection state.

Because data is browser-local:
  • Clearing site data (via browser settings) will erase your LysiPOS data — always export a backup first.
  • Different browsers (or different browser profiles) hold separate LysiPOS databases.
  • Incognito / private windows won't persist data between sessions.

17. Keyboard & barcode tips

  • On the POS screen, focus the search box and type or scan a barcode → Enter adds the matching product.
  • In cart quantity boxes, type a number and press Tab to commit.
  • Use Ctrl / Cmd + P from the receipt dialog to print, or click Print receipt.
  • The sidebar has a theme toggle (🌓) for switching between dark and light.

18. AI Assistant

LysiPOS ships with an optional chat assistant that can read your store data and this manual, then answer questions or make suggestions ("what should I restock", "how were sales last week", "explain tax-inclusive pricing"). It's off by default.

Enable it (Admin)

  1. Go to Settings → AI Assistant.
  2. Flip Enable AI Assistant to On.
  3. Pick a Provider:
    • Anthropic (cloud) — needs an API key from console.anthropic.com. Best quality, uses your internet + your quota.
    • Ollama (local) — runs entirely on your computer, no data leaves the machine. Install from ollama.ai, then ollama pull llama3.2 (or any model of your choice).
    • LM Studio (local) — runs the "Local server" feature of LM Studio (default port 1234). Any GGUF model you've loaded works.
  4. Fill in the Base URL, Model, and API key (if any).
  5. Click Test connection. Fix any errors before saving.
  6. Click Save AI settings. A ✨ Ask AI button now appears in the top bar for permitted users.

Who can use it

  • Admins always have access when AI is enabled.
  • Managers only if the AI Assistant access flag is set on their user (Users → Edit).
  • Cashiers never.

What it can see

Each request bundles a compact snapshot of your store as context:

  • Business name, currency, tax settings, today's date.
  • Up to 120 active products (name, SKU, stock, price, cost, category, supplier) and every low-stock item.
  • Last-30-day sales: totals, per day, top products, revenue by category, revenue by cashier.
  • Last-30-day expenses total and breakdown by category.
  • An outline of this manual so it can answer "how do I…" questions.
Anthropic mode sends this data to Anthropic's API. Ollama and LM Studio keep everything on your local machine. Choose the provider that matches your data-handling requirements.

CORS notes for local providers

  • Ollama: browsers block cross-origin requests by default. Before launching Ollama, set the environment variable OLLAMA_ORIGINS to the origin serving LysiPOS (e.g. http://localhost:8080), or * for any origin.
  • LM Studio: in the Developer tab of LM Studio's local server, enable Serve on network and Enable CORS. Restart the server after changing.

Where your keys live

AI provider settings (URLs, API keys, model name) are stored in a separate IndexedDB entry that is not included in exported JSON backups. They stay in whatever browser you configured them in.

19. Dev Console (Admin)

Open 🛠️ Dev Console from the sidebar. It's the one-stop page for troubleshooting and quick maintenance without leaving the app.

Session & storage

  • Session — current user, app/DB version, user-agent, online status, PWA display mode, camera-scanner support, File System Access support, active service workers, and browser storage estimate.
  • Storage — row counts and estimated size per IndexedDB store, with a per-store Clear button (the settings store is protected).

Users — quick actions

A compact table of every user with, per row:

  • Change password — set any user's password. Requires 4+ chars and a confirmation. Stored SHA-256 hashed; no plaintext is kept.
  • Disable / Enable — toggle without deleting.
  • Change role — flip between admin / manager / cashier.
  • Delete — removes the user (you can't delete yourself).
  • + Ensure default admin — re-adds admin@lysipos.local / admin123 if no working admin exists.

Audit log

Last 100 recorded actions (logins, sales, imports, password changes, etc.). Download the full log as CSV, or clear it entirely.

Console output

The app captures console.log/info/warn/error and unhandled errors from the moment the page loaded — helpful when you need to diagnose an issue without opening DevTools. Filter by level or clear as needed. The ring keeps the last 400 entries.

Danger zone

  • Unregister service worker — forces the next reload to fetch fresh app code. Use when a hard-refresh isn't picking up an update.
  • Delete IndexedDB & reload — wipes the entire database file and reloads. Cleaner than "Reset all data" if the DB itself seems corrupt.
  • Reset all data & reseed — clears every store and re-seeds the demo store.
All three are destructive. Export a backup from Settings → Data first if you might want the data back.

20. FAQ & troubleshooting

The Install button never appears

Chrome-family browsers only show the install prompt on secure origins (https:// or http://localhost) and after the service worker has registered. Serve the folder with a local HTTP server (e.g. python -m http.server 8080) and reload once.

I opened the file and it looks unstyled

You probably double-clicked index.html. Some browsers block ES modules from file://. Serve the folder over HTTP as above.

The receipt is huge on paper

Use your browser's print dialog to switch to a thermal printer / narrow paper size. The receipt is 80 mm-friendly and the rest of the UI is hidden in print CSS.

Tax numbers look off

Check Settings → Tax included in price. When your catalog prices already contain tax, this must be Yes, otherwise tax will be double-counted.

I forgot the admin password / can't log in after an import

Open restore-admin.html from the same folder (or same URL) as the app — it's a standalone recovery page that talks directly to the browser's IndexedDB and doesn't require login. From there you can:

  • Ensure default admin — re-adds admin@lysipos.local / admin123 if none exists.
  • Reset any user's password — pick a user, type a new password, done.
  • Delete all users & add default admin — nuclear option that keeps products, sales, and settings.
  • Delete the entire database — last resort; wipes everything so the app re-seeds a demo store on next load.

As an extra safety net, the app also re-adds a default admin automatically whenever an import finishes without leaving a working admin behind.

Can multiple devices share data?

Not out of the box — data is local to each browser. Use Export / Import to move data between devices. Adding real multi-device sync would require a small backend (out of scope for this offline PWA).

Where do I file feedback or bugs?

Since this is a self-hosted static app, feedback goes wherever your team gathers it — a shared doc, an internal tracker, or straight into app.js. The codebase is intentionally small and readable.
